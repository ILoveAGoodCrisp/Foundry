# H2 and H3/ODST lighting previews

`shared_nodes.blend` is generated by `blender/build_lighting_nodes.py` using
Blender 5.2. Existing socket identifiers are retained. The Foundry Node engine
menu distinguishes **Halo 3 / ODST** from **Reach / Halo 4+**; the former
`Halo 3+` menu identifier retains the old Reach graph. Imports select the
appropriate branch explicitly. Reach's existing emissive graph is unchanged.
H1 estimates its optional near-source softening area automatically.

Halo Light has an engine menu with separate H3/ODST dynamic and baked models,
an H2 baked sphere preview, and the previous H1/H2 dynamic and Reach models.
The light properties panel exposes the imported game parameters and drives
the corresponding node inputs. Use Cycles for distance-dependent light
shaders. Reload linked libraries/reopen the scene after updating Foundry;
older locally appended groups retain their old behavior until replaced or
the material/light is reimported. Local user graphs are not silently replaced.

## Implemented models

* H1 emissives: triangle area is estimated from the mesh triangulation (mean
  triangle area for each n-gon), stored as a face attribute in local scene
  units squared, and adjusted in the shader for object scale. The estimates
  refresh with material/mesh properties, after live-preview mesh changes, and
  before rendering. The old H1
  Triangle Area inputs are hidden compatibility sockets. Missing geometry
  estimates bypass softening; they do not introduce a fixed arbitrary area.

* H3/ODST dynamic: `(1-d*d/R/R)/(d*d+s)`, zero outside R, the cosine cone
  exponent and spherical floor. Diffusion is in squared world units, not a
  linear fade start or a shadow radius. The graph uses a point carrier for
  spotlights so Blender does not apply an extra spot ramp or clip the spherical
  floor. Source type and cone angles remain available for export.
* H3/ODST baked: the solid angle of the fixed 0.02-wu source, type factors
  0.003/0.025/0.005, optional linear near/far windows, and a linear angular ramp
  for circular spots. Standard Blender power is converted with `P/(4*pi)` and
  the appropriate far-field coefficient; importing/exporting Halo intensity
  preserves tag units. Directional intensity uses the exact solid angle at 1 wu.
  H3/ODST lighting-info exports use radians, world-unit attenuation distances,
  independent attenuation flags and nonzero configurable directional diameters.
  Automatic ordinary lights leave far attenuation disabled.
* H2 emissives: `24 * shader_power * face_power_scale` per surface area, the
  luminance darkening/clamping curve after gamma-2.2 decoding, and optional
  `exp(-0.693*d/half_life)`. Shader/template/runtime half-life is imported;
  nonzero face half-life overrides it. Generic Blender emission conversion
  divides strength by 24, **not by patch area**: density already integrates
  over area in both Blender and the supplied engine formula.
* H3/ODST emissives: density `power` for per-unit-area lights, otherwise
  `0.3*power/connected_patch_area`; multiply by `1-frustum_blend`, the focus
  lobe and the linear distance window. Disabling authored attenuation still
  gives the engine's 20–21-wu window. Automatic export with zero distances
  uses that same window. Face overrides retain their explicit zero/black mask.
* H2 baked sphere lights: gamma-2.2 color decoding, brightness and lightmap
  scale before the luminance clamp, the 1/0.95 compensation, emitting area
  `4*pi*(0.1*radius)^2`, and half-life. Runtime lights keep their previous
  dynamic preview unless the baked model is selected.

## Limits of the preview

The supplied research did not establish H2 per-photon energy normalization or
H3 emissive per-sample cosine/pi normalization. Those previews reproduce
relative power, area, color and falloff, not calibrated game exposure. The
runtime's BRDF, SH lightmap decoding, exposure and self-illumination exposure
are separate from these light-source models.

Cycles supplies the current ray segment length, not the full distance traveled
by an H2 photon through every bounce. Half-life therefore matches the direct
segment; it does not reproduce the photon mapper's cumulative bounce survival.
H2 frustum source area, scenario-level half-life/scale overrides, and animated
size are not reconstructed. Emissive map sampling is not reconstructed by the
constant-color wrapper. Rectangular light projections, directional spatial
footprints and projected shadow-map gels remain Blender approximations; the
directional diameters are preserved for the game exporter.

Patch-area attributes are refreshed with Foundry mesh properties and measured
in local mesh space, converted to square world units. Apply object scale and
refresh the preview after editing geometry for accurate total-power patches.
Different scaled instances of a shared mesh cannot have different patch-area
attributes. Standalone emissive groups also expose an explicit Patch Area
input, used when the mesh has no area attribute.

## Evidence and validation

Based on the supplied `halo2_halo3_odst_fov_and_light_power_for_foundry.md`:
H3 tool 0x140236930/0x140236740 (type scales), 0x140236C90 (ramps),
0x140236FB0 (solid angle), 0x140238C90 (surface power/window),
0x14023A8A0 (focus), and `calculate_simple_light`; H2 tool 0x4E8C73
(24 * power * area), 0x4E8EB3/0x4E8E6A (half-life), 0x65F8C0
(luminance curve), and 0x4EAFE0 (baked object lights). Reach was not verified
by that research and is not assigned H3's model.

`test_lighting_models.py` checks the numerical relationships;
`test_lighting_models_blender.py` renders the shipped graphs in Cycles and
checks actual point/spot/sun illumination, H2 clamping/radius, emissive power,
half-life and distance windows. `test_h3_lighting_tags.py` saves/reopens native
H3/ODST definitions; the attenuation and H2 BSP tests cover import/export
units, flags, shader defaults and explicit zero overrides.
